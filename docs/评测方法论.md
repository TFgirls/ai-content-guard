# 评测方法论

> 这份文档解释「这个项目的效果数字是怎么来的」，以及「这些数字能证明什么、不能证明什么」。
> 面试时如果被问「你的准确率怎么测的」，直接对照本文回答。

---

## 一、为什么审核类项目必须有评测

审核系统的失败有两种，代价完全不同：

| 失败类型 | 表现 | 业务后果 |
|---|---|---|
| 误报（FP） | 正常内容被判违规 | 商家投诉、审核人力浪费 |
| 漏检（FN） | 违规内容被判通过 | 合规风险、平台处罚 |

只报「准确率」是没意义的——一个把所有内容都判违规的系统，在违规占比高的样本集上准确率也能很好看。所以这里同时看精确率和召回率，并且**允许两者有不同的取舍**。

---

## 二、样本设计

### 主评测集（18 张）

| 类别 | 数量 | 设计意图 |
|---|---|---|
| 明显违规（`ad_*`） | 6 | 词表能直接命中的确定性违规 |
| 正常文案（`ad_*`） | 6 | 不应误报的对照组 |
| 语义变体违规（`hard_01~04`） | 4 | 换说法但语义仍违规，词表命不中 |
| 易误报正常样本（`hard_05~06`） | 2 | 含「第一」「最近」等易误伤词 |

**关键设计**：故意把「规则能抓的」和「规则抓不到的」分开。否则只看总准确率，无法判断到底该不该引入大模型。

### 噪声用例（9 条，文本层）

不生成图片，直接喂脏文本。原因见第五节。

覆盖：跨行断词、字间空格、全角符号、大小写变体，以及 3 条「不该误报」的对照。

## 三、指标定义

### 判定指标

```
精确率 precision = TP / (TP + FP)     判违规的里面，真的违规多少
召回率 recall    = TP / (TP + FN)     真违规的里面，抓出来多少
F1              = 2PR / (P + R)
准确率 accuracy  = (TP + TN) / N
```

### 改写指标

| 指标 | 定义 | 为什么需要 |
|---|---|---|
| 改写执行率 | 成功拿到改写文本的条数 / 违规条数 | 区分「没改」和「改得干净」 |
| 零残留率 | 改写后词表零命中的条数 / 执行成功的条数 | 量化改写是否彻底 |
| 平均残留数 | 改写后仍命中的违禁词个数均值 | 比「合格率」更细的粒度 |

**注意**：改写执行率低于 100% 时，零残留率只在执行成功的那部分里统计，不能合并计算——否则「没改」会被算成「改坏了」。

## 五、这些数字能证明什么

**能证明**：
1. 链路是通的：图片进、结构化结果出，中间每一环都有人为设计的信号。
2. 两种漏检成因是分开的：语义变体靠大模型补（60%→100%），OCR 噪声靠归一化补（50%→100%）。
3. 改写不是「调一次就算」：有执行率、残留率两个可核对的数。

**不能证明**：
1. **不能代表真实分布**。18 张是白底黑字的合成图，标签由脚本生成。真实电商图有复杂背景、艺术字、多列排版，指标一定会掉。
2. **不能证明改写后的语义合规**。复检只扫词表，能证明原违禁词被清掉，证明不了新文案没有新的暗示性违规。
3. **不能外推到大词库**。词表只有 37 个词（4 类），真实违禁词库是万级。

**面试时的正确表述**：
> 「我在 18 张自建标注样本上做到 100%，但这只证明链路和策略有效。真实图我预期会掉到 70–80%，主要漏在艺术字识别和委婉表达上——这是我下一步要补的。」

## 六、一个容易忽略的坑：噪声必须用文本测

最初想用「生成带空格/全角的图片」来测归一化的价值，结果测不出来——**RapidOCR 自己就会把全角符号和字间空格规范化掉**。

所以噪声用例改成直接喂文本层，绕开 OCR：

```
{"text": "无效退\n款", "target": "无效退款", "label": 1, "note": "跨行断词"}
```

同一批用例跑两遍 `scan_rules(text, normalize_text=False/True)`，得到开/关对比。

**教训**：测试手段要和被测环节对齐。想验证文本处理的鲁棒性，就不要让 OCR 挡在中间。

## 七、复现方式

```bash
python tools/make_samples.py                    # 生成样本与标注
python -m src.evaluate --no-llm                 # 仅规则
python -m src.evaluate                          # 规则 + 大模型
python -m src.evaluate --with-rewrite           # 额外跑改写指标（更费额度）
```

报告输出到 `reports/eval_report.md`，含逐条明细、混淆矩阵、失败样本与归一化对比。
